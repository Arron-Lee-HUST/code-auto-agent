# 产品需求文档（PRD）

## 定位
将自然语言需求转化为可追踪研发交付物。确定性工作流组织专业 Agent，结构化契约、质量门禁与审批策略控制风险。

## 角色
- 需求提出者：描述目标、背景和约束。
- 产品/业务负责人：澄清业务规则并确认验收标准。
- 研发工程师：审查技术方案和代码变更。
- QA：维护验收场景、执行测试。
- 技术负责人/运维：审批高风险变更与发布。

## 核心流程
1. 创建需求工作流。
2. 生成结构化需求规格，标记假设和开放问题。
3. 分析仓库（当前 MVP 只记录元信息，不克隆仓库）。
4. 生成技术方案和有依赖关系的任务列表。
5. 执行质量门禁并输出可追踪产物。
6. 后续版本接入真实模型、隔离执行、自动测试、PR 和 staging 验收。

## MVP 范围
包含 REST API、状态机、Pydantic 规格、四类本地演示 Agent、SQLite、产物追踪、测试和 CI。
不包含真实 LLM、仓库克隆、源码修改、shell、自动 PR/部署、身份认证和分布式任务队列。

## 验收标准
- API 可创建工作流并返回明确状态。
- 工作流生成需求规格、仓库分析、技术方案和质量审查产物。
- 关键上下文缺失时状态为 `blocked`，并记录开放问题。
- 非法状态迁移被拒绝。
- 测试和静态检查可在 CI 运行。
