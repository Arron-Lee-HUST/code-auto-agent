# 安全设计

## 当前版本
不克隆仓库、不执行 shell、不修改 Git、不创建 PR、不部署；只保存需求、仓库 URL 和约束。业务需求可能敏感，应按业务数据管理。

## 生产化前必须完成
1. 身份认证、授权、租户隔离和速率限制。
2. 密钥由 Secret Manager 注入，不写入 prompt、日志或 artifact。
3. README、代码注释、issue 和仓库文件均视为不可信输入，不能提升为系统指令。
4. 仓库执行放在隔离容器或微虚拟机；限制 CPU、内存、磁盘、时长、系统调用和网络。不能将普通 Docker 视为所有威胁模型下唯一边界。
5. Git 读写权限分离，每次写入限定分支、路径和任务范围。
6. 危险命令、凭据访问、生产数据修改和发布设策略门禁。
7. 高风险动作要求人工审批并记录审批人、时间、目标和结果。
8. 审计工具调用和外部副作用，日志脱敏并设保留策略。
9. 依赖锁定、漏洞扫描、SBOM、签名制品和最小权限 CI。
10. Webhook 验签、重放保护、幂等处理和外部状态对账。

风险分级：低（只读分析/文档）、中（测试代码）、高（认证/权限/迁移/支付）、严重（生产发布/不可逆数据操作）。高/严重风险不得由同一 Agent 自我审批。
